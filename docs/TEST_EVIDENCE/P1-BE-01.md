## 4. Implemented Behavior

1. **Pure Application Factory (`createApp`):**
   - Does not bind to a TCP socket or initiate database connections on import.
   - Accepts injectable dependencies (`env`, `logger`, `readinessProvider`, optional `extraRouter` for tests).
   - Configures reverse-proxy hop trust via `config.TRUST_PROXY_HOPS` (default `0`).
   - Disables `X-Powered-By`.

2. **Frozen HTTP Endpoints (`/api/v1`):**
   - `GET /api/v1/health/live`: Returns HTTP 200 with `{ data: { status: "ok", version: "0.1.0" }, meta: { requestId } }` even when database is unready.
   - `GET /api/v1/health/ready`: Returns HTTP 200 when dependencies are ready; returns HTTP 503 when dependencies are unready. Identical response shape `{ data: { ready: boolean }, meta: { requestId } }`.

3. **Standardized Error Handling:**
   - Centralized Express 5 error handler matching `ApiErrorResponseSchema`.
   - Unknown routes return HTTP 404 `NOT_FOUND`.
   - Malformed JSON payloads return HTTP 400 `INVALID_INPUT`.
   - JSON payloads above 64 KiB return HTTP 413 `PAYLOAD_TOO_LARGE`.
   - Unapproved Origin headers return HTTP 403 `FORBIDDEN`.
   - Unexpected server errors return HTTP 500 `INTERNAL_ERROR` with generic sanitized message, hiding stacks, internal paths, and credentials.

4. **Security and Request IDs:**
   - Generated using `crypto.randomUUID()`.
   - Attached to `X-Request-ID` response header and JSON payload metadata/error.
   - Client-provided IDs are untrusted and discarded.
   - Requests without an Origin header are permitted for CLI/health monitors.
   - Unapproved Origin headers are rejected with 403.
   - Helmet headers configured (`nosniff`, strict CSP, `frameAncestors: none`).
   - Pino logs redact credentials, authorization headers, cookies, request bodies, and database URIs.

5. **MongoDB Connection and Readiness Manager:**
   - Connection attempts bounded by 5-second `serverSelectionTimeoutMS` and `connectTimeoutMS`.
   - Logs only safe connection state (`state`) and fixed diagnostic categories (`category: DATABASE_LIFECYCLE`, `DATABASE_CONNECTION_TIMEOUT`, `DATABASE_RUNTIME_ERROR`).
   - Never serializes URIs, passwords, usernames, query strings, or raw driver exceptions into logs.
   - In offline development without `MONGODB_URI`, HTTP service starts cleanly, serves liveness (200), and reports readiness as false (503).
   - `MOCK_DATABASE=true` enables mock readiness in development/test with prominent logged warning banner; strictly rejected in `NODE_ENV=production`.
   - Graceful shutdown handles `SIGINT` and `SIGTERM` by closing HTTP listener and disconnecting Mongoose cleanly.

6. **Shared Contracts Domain Enums:**
   - Added `PlanCodeSchema` (`FREE`, `PAID_250`, `PAID_500`, `PAID_1000`, `VIP`).
   - Added `InterviewStatusSchema` (`DRAFT`, `PREFLIGHT`, `READY`, `ACTIVE`, `RECOVERING`, `COMPLETED`, `TERMINATED_INTEGRITY`, `ABORTED_PREFLIGHT`, `ABORTED_SYSTEM`, `EXPIRED`).

7. **CI Workflow (`.github/workflows/ci.yml`):**
   - Configured on `ubuntu-latest` with `contents: read` permissions and Node.js 22.
   - Executes `npm ci`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, and `npm audit --omit=dev`.

## 8. Security Findings & Verifications

- **Secret Scanning:** Codebase searched; zero raw secrets, passwords, or provider API tokens committed.
- **URI Credential Masking:** Connection strings containing user:password are stripped via `sanitizeUri()` (`mongodb+srv://***:***@host/db`) before logging.
- **Pino Redaction:** Authorization headers, cookies, request bodies, and fields matching `password`, `token`, `secret`, `apiKey`, `connectionString`, and `MONGODB_URI` are suppressed.
- **MongoDB Diagnostic Hardening (R1-01):** MongoDB manager logs only fixed diagnostic categories (`category: DATABASE_LIFECYCLE`, `DATABASE_CONNECTION_TIMEOUT`, `DATABASE_RUNTIME_ERROR`) and connection `state`. It never serializes URIs, credentials, query parameters, connection error strings, or driver exceptions.
- **Exception Sanitization:** 500 handler logs full errors internally via logger but returns generic message `Internal server error` to the client, concealing error messages, internal paths, and stack traces.
- **Request ID Forgery Protection:** Client-supplied `X-Request-ID` is completely ignored; a fresh `crypto.randomUUID()` is generated server-side for every request.
- **Origin Boundary:** Browser requests carrying unapproved Origin headers are rejected with 403 Forbidden.
- **Payload Size Capping:** Body parser rejects payloads > 64 KiB with HTTP 413 `PAYLOAD_TOO_LARGE`.
- **Production Guardrails:** `MOCK_DATABASE=true` is rejected by Zod schema validation in `NODE_ENV=production`.
- **Zero Cloud Connections:** No connection made to MongoDB Atlas or paid cloud providers.

## 12. Remediation Verification: P1-BE-01-R1

The changes requested by the Principal Architect in `P1-BE-01-R1` have been implemented and verified:

### R1-01: Remove Sensitive MongoDB Diagnostic Logging
- **Implementation:** `apps/api/src/integrations/mongodb.ts` was refactored to remove all URI and raw exception logging. Logs strictly emit safe metadata: `state` (`connecting`, `connected`, `disconnected`, `reconnected`, `failed`, `error`) and fixed diagnostic `category` (`DATABASE_LIFECYCLE`, `DATABASE_CONNECTION_TIMEOUT`, `DATABASE_RUNTIME_ERROR`).
- **Evidence:** `apps/api/tests/mongodb-logging.test.ts` executes synthetic connection and runtime failure scenarios containing recognizable fake credentials (`super_secret_agent_user`, `TopSecretP@ssw0rd!987`, `fake-cluster-999.mongodb.net`, `MongoServerError`). The test suite asserts that zero credentials, URIs, or driver exception messages appear in captured logs.

### R1-02: Non-Blocking MongoDB Startup & Liveness Independence
- **Implementation:** `apps/api/src/server.ts` was refactored to implement the exact mandated 7-step startup sequence. The HTTP listener starts immediately, serving `GET /api/v1/health/live` (200 OK) while the bounded MongoDB connection attempt runs asynchronously without blocking HTTP startup. Readiness reports 503 until connection resolves, and graceful shutdown cleanly handles shutdown even if a connection attempt is still pending.
- **Evidence:** `apps/api/tests/startup.test.ts` executes deterministic tests using an injected `DelayedMongoManager`. The test verifies that `live` returns 200 immediately, `ready` returns 503 until connection resolution, `live` remains 200 even on connection failure, and shutdown resolves safely with a pending connection.

### R1-03: Strict MOCK_DATABASE Environment Validation
- **Implementation:** `apps/api/src/config/env.ts` was updated with a strict Zod preprocessing and union schema accepting only boolean `true`/`false`, string `"true"`/`"false"`, or string `"1"`/`"0"`. Any other explicitly supplied value (including `"tru"`, `"enabled"`, `""`, `"yes"`, `"2"`, `null`) is strictly rejected. Unset values default cleanly to `false`. In `NODE_ENV=production`, `MOCK_DATABASE=true` remains strictly forbidden.
- **Evidence:** `apps/api/tests/config.test.ts` verifies acceptance of all approved boolean and string variants, defaults when unset, and explicit rejections of `"tru"`, `"enabled"`, `""`, and invalid strings.

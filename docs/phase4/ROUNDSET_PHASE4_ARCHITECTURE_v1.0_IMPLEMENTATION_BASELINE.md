## 1. Architecture and hard trust boundaries

```text
Browser (P5 voice later) -- HTTPS /api/v1 --> Express + P2 auth/ingress
        memory-only Bearer                     |       P3 entitlement/usage ledger
        stable operation key                   |
                                               +-- Interview Controller
                                               |     durable state + server clock
                                               |     P3/Q1 short transaction
                                               |     generation intent + attempt fences
                                               |     public event projection
                                               |
                                               +-- AI Gateway (only live provider egress)
                                                     account budget admission
                                                     provider-specific consent gate
                                                     Groq Qwen primary
                                                     Cloudflare Qwen [OFF]
                                                     deterministic mock
                                               |
                                               +-- MongoDB durable events/claims/receipts
```

No application service gets a direct production provider adapter without a valid, unique, unexpired **dispatch permit** plus all-or-none provider budget admission. Candidate attempt admission must also conditionally **write-fence the current interview/generation claim** inside the same Mongo transaction as the accepted P2 user/session write fence, provider-account budget receipt and attempt/permit insertion; a snapshot read of the interview claim does not serialize with abort/reclaim. For private candidate data, the permit and budget reservation are committed together with a short transactional P2 authorization **write fence**; a prior read alone is not the permit. Synthetic-only probes must be separately labeled and isolated **by input and additional spike subcap**, but use the **same account budget** when provider credentials share a real tenant. A permit proves authorization **at its durable admission commit**, not irrevocable authorization at a later physical network send (§3). No external call occurs inside a Mongo transaction or a transaction callback that may be replayed. External inference is **at-least-once** under ambiguous failures; authoritative interview state/credit/turn publication is constrained **exactly once** through unique keys and transactional CAS.

## 2. IDs, scopes and distinct counters

| Name | Meaning and authoritative scope |
|---|---|
| `userId` | Current P2 principal (server-derived); `sessionId`, current `sessionEpoch` verified through P2. |
| `interviewId` | Server-generated owner-scoped session ID. |
| `reservationId`, `reservationPeriodKey` | P3 ledger identity and Asia/Kolkata start-month; cannot be moved across periods. |
| `operationId` | Stable logical inference goal: START/Q1 or one finalized-turn→next question. |
| `generationEpoch`, `claimNonce` | Fencing token for currently authorized controller lease. |
| `attemptNo` | **Per-remote-dispatch**, monotonically increasing for an `operationId`, including JSON repair, optional PLAN+Q1 second call and new provider fallback. Never reuse it for a second network send. |
| `attemptId` | Unique global remote network attempt and budget receipt ID; unique together with `(operationId, attemptNo)`. |
| `dispatchPermitId`, `permitNotAfter`, `authorizationEpochAtPermit` | One-use, bounded permit tied to `attemptId`, P2 owner/session/epoch/consent revision, **guarded interview `generationEpoch`/`claimNonce` and stateVersion**, provider account and **canonical source-derived `dataClasses` set/hash** at atomic admission. A permitted attempt cannot be replayed or have its payload/class set silently changed for a fresh send. |
| `idempotencyKey` | Client's stable operation key; scoped to authenticated user + route + resource, bound to canonical payload digest and contract version. |
| `publicSequence` | Candidate-facing lifecycle event cursor and optimistic turn precondition; internal attempt/audit events never increment this. |
| `stateVersion` | Internal CAS/version counter; may change without changing candidate `publicSequence`. Do not use as a substitute for client-visible expected turn. |
| `promptVersion`, provider/model | Immutable private question-generation provenance; not exposed in P4 candidate DTO. |

A remote retry/repair requires a **fresh** `(attemptNo, attemptId, admissionReceipt)`, but may remain within the same live controller lease/`generationEpoch` if enough time remains. A reclaimed controller claim gets a new nonce/epoch and may continue the same stable `operationId` with a higher `attemptNo`. Unique indexes on both `attemptId` and `(operationId,attemptNo)` remain valid: **do not add a `dispatchIndex` merely to mask accidental attempt-number reuse.**

## 3. P2 auth, consent and commit fencing

- Every P4 GET/POST needs Roundset Bearer auth and actual P2 current user/session/epoch checks plus owner isolation. Expired JWT ⇒ explicit `/auth/refresh` under P2 cookie+CSRF; retry only safe idempotent P4 commands with **identical key and canonical body**. Refresh cookie alone never authorizes an interview route. Browser mutations honor strict Origin and Fetch Metadata, and trusted edge ingress in proxy mode. CORS explicitly permits the chosen `Idempotency-Key` header.
- **User-level provider egress authorization point (R4-M04, R5-H01/M01, owner O-05):** For each candidate-data remote attempt, commit **one short Mongo transaction** that (i) applies the accepted **P2-owned guarded user+session write fence** (ACTIVE, matching epoch and consent), (ii) performs an actual **guarded write/CAS on the current `interviews` document** matching owner, permitted status, `generationEpoch`, `claimNonce`, live lease and deadlines, (iii) checks **every server-derived data class** in the complete prompt/derived-summary provenance against the selected provider/model/current consent and policy revision, and (iv) atomically records a **one-use `dispatchPermit`, unique `attemptId`, and complete shared provider-account budget reservation**. For the interview CAS use an actual version-advancing write (e.g. conditional `$inc: {stateVersion:1}`); a snapshot read or optimized no-op update is insufficient. All terminal/reclaim/abort/complete transitions that invalidate the claim write the same interview document. Commit is the admission **authorization linearization point**, not physical network-send time. On stale claim/transaction conflict abort all attempt/permit/budget writes, re-read current state and retry only eligible deterministic Mongo work with stable attempt identity; do not send or silently admit. No network send can start on an unconfirmed/ambiguous permit; reconcile uncertain commit by attemptId before proceeding. New dispatch permits after committed withdrawal/deletion/claim termination are forbidden. Never hold the Mongo transaction open across HTTP.
- **Post-permit withdrawal semantics (not a false atomic-send guarantee):** Between a valid permit and actual HTTP egress, an account may be revoked. Immediately before send, check permit expiry/claim/cancellation and re-read authoritative P2/consent state; suppress the send when revocation is known. Invalidate pending unsent permits and attempt best-effort cancellation of admitted work on deletion, suspension and consent withdrawal; always reject stale results at publication through the P2 write fence. Nevertheless, a later revocation can occur **after the final check but before or during network transmission**: an attempt admitted while consent was valid may still begin or complete network egress. This residual window and the owner-approved treatment of such already-admitted work must be accepted under **O-05 before real private-text inference**. Do not assert strict physical send-time cutoff or remote recall without separately approved coordination. Permit TTL, max post-permit delay, cancellation acknowledgment and policy version must be bounded and testable; synthetic-only traffic is permitted before this privacy gate.
- **Claim/permit lifetime:** The interview admission write increments only internal `stateVersion` (not `publicSequence`) while keeping the authorized `generationEpoch`/`claimNonce` stable for that live attempt. Later Q1/Q-next publication must read the updated authoritative version/claim and independently CAS current state; it may not reuse a pre-permit `stateVersion` as if unchanged. Once abort, terminalization or lease reclamation writes the interview first, no old-generation permit can commit. If permit commits first, later abort may invalidate it; recheck before send and suppress stale result publication. The unresolved post-permit network-send race stays O-05. For PRE_START, require READY and live START lease; for POST_START, require a currently eligible ACTIVE/owner-resumed claim and effective deadline. RECOVERING alone never authorizes inference.
- **Permit/usage states:** An attempt can transition `ADMITTED → CANCELLED_BEFORE_SEND` only if an atomic send claim never occurred, permitting proven-unused token reservation reversal against its original accounting window. Once `SEND_CLAIMED`, `DISPATCHED`, or `UNKNOWN`, conservative provider usage remains accounted even if cancellation is requested or the network returns ambiguously. New network retries always need a fresh permit/admission/attemptId. Never treat an unacknowledged permit-transaction commit as authorization to send.
- **Commit-time authorization serialization on every user-originated P4 write that can create, resume, extend, or publish private state:** Apply the same **conditional transactional write/CAS** to P2's authoritative `users` document and the current authenticated P2 `sessions` document during **create + P3 reserve**, **preflight→READY**, **START Q1 publication**, **finalize answer/next-intent**, **advance Q-next publication**, and **resume/pause credit**. Guard `accountStatus=ACTIVE`, matching `userId`, session ownership/ACTIVE/expiry, `sessionEpoch`, current consent eligibility and relevant authorization versions. A read-only snapshot is insufficient. Terminal owner `/complete` and `/abort` must also establish current owner authorization; any mutation that could create or restore data uses the same shared write fence. No model call occurs inside the fence transaction.
- **P2 integration contract is not yet implemented/accepted:** The P2 module must expose a `fenceAuthorizedMutation({userId,sessionId,expectedEpoch,requiredConsent}, mongoSession)`-equivalent primitive whose guarded **write** conflicts with P2 `PENDING_DELETION`, suspension, epoch/consent mutation and single-session revocation. The exact field/update is owned and approved by P2; P4 must not add an unapproved field or assume a no-op update provides conflict serialization. All steps in a candidate mutation share the same Mongo `ClientSession` with P3/quota where required. Test the P2 mutation ordering on a replica set before enabling P4 writes.
- **Deletion and privileged cleanup ordering:** P2 first commits `PENDING_DELETION`/epoch fence, thereby blocking any *later* P4 create/resume/publication; an in-flight P4 mutation that serializes first can be removed by the subsequent idempotent purge. Sweep all P4 collections only after the P2 fence, and support a separately authorized **internal cleanup/reconciliation** pathway after revocation that can terminate/delete but **cannot** create interview content, renew user state, dispatch inference or reserve credit. Such internal cleanup is not a bypass on candidate GET/POST routes. Require transaction race tests in both orderings.
- **Global policy activation is separate from P2 per-user consent:** A change to global provider eligibility is not automatically serialized by a user/session write fence. Phase 4 v1 does **not** silently hot-swap a stricter policy in-flight. Until an owner-approved rollout protocol exists, new dispatch is blocked during policy rollout; drain/cancel outstanding provider operations by bounded leases, activate the new revision consistently, and reopen admission only after the consent/provider classification checks agree; late old-revision provider results must also fail a fresh publication eligibility check and never commit after a stricter policy takes effect. If immediate dynamic activation is later required, introduce an approved durable global policy generation/commit fence or proven equivalent, not a claim that a P2 user write solves it. Treat this as policy/deployment gate **O-12**, not as an observed Phase 4 exploit.
- **Data-class closure (R5-H01):** Gateway classification is computed by the server from **all** source parts of each outbound message and the transitive source lineage of every derived `ContextSummary`/prompt fragment, not chosen by a caller or inferred from one top-level field. Persist canonical distinct `dataClasses` (`SYNTHETIC`, `USER_TRANSCRIPT`, `USER_DOCUMENT`) on the attempt and permit. `USER_TRANSCRIPT` covers real candidate answers and candidate-session text; `USER_DOCUMENT` covers real resume/JD/repository content, including any derived summary. A mixed transcript+document prompt must carry **both** real-data classes and pass **all-of** current provider-specific eligibility and consent. Unknown/missing source provenance, omitted constituent class, stale class hash or unsupported mixture fails closed with no attempt admission or egress. A hierarchy/maximum sensitivity is not equivalent to independent permissions. **Class consent never substitutes for checking each root/ancestor record's owner and interview scope (§4/R6-M01).** The final outbound class union must be nonempty; candidate-provided role/track/configuration metadata and server-normalized derivatives of it count as `USER_TRANSCRIPT` even when presented as trusted plan tags. An all-static prompt with no user source cannot silently become a `SYNTHETIC` attempt; only an explicitly registered synthetic-fixture operation may qualify. `SYNTHETIC` is permitted **only exclusively** for audited synthetic fixtures, never together with real candidate data; candidate-supplied text never becomes synthetic through quoting or summarization. Do not log source content or hashes of raw personal text. On model repair and **each** separately permitted provider fallback, recompute/recheck the complete canonical set; Cloudflare remains OFF until authorized and independently approved for *every* class.

## 4. AI provider contract, validation and time budget

```ts
// Types are design shapes, not executable source or frozen public contracts.
type Purpose = 'START_BUNDLE' | 'PLAN' | 'QUESTION' | 'FOLLOW_UP' | 'CONTEXT_SUMMARY';
// EVALUATION | REPORT reserved for P7, not callable as Phase 4 feature.
type ProviderId = 'GROQ' | 'CLOUDFLARE' | 'MOCK';
type DataClass = 'SYNTHETIC' | 'USER_TRANSCRIPT' | 'USER_DOCUMENT';
// INTERNAL trusted builder shapes, NOT client/provider wire DTOs.
interface SourceDescriptor {
  ref: string; // Server-controlled identity, never prompt/client-supplied.
  kind: 'TRUSTED_TEMPLATE' | 'SYNTHETIC_FIXTURE' | 'CANDIDATE_RESPONSE' |
        'CANDIDATE_CONFIGURATION' | 'CANDIDATE_DOCUMENT' | 'DERIVED_SUMMARY';
  inheritedClasses: ReadonlyArray<DataClass>; // Closure of every ancestor/source.
  ancestorRefs: ReadonlyArray<string>; // Derived summaries retain transitive lineage.
  // Descriptive only: MUST verify against authoritative persisted source ownership.
  scope: { type: 'SERVER_TEMPLATE'; templateId: string; templateVersion: string }
       | { type: 'SYNTHETIC_FIXTURE'; fixtureId: string; fixtureVersion: string }
       | { type: 'USER_INTERVIEW'; userId: string; interviewId: string;
           recordId: string; recordVersion: string };
}
interface GenerationIntent {
  operationId: string; generationEpoch: number;
  attemptId: string; attemptNo: number;
  interviewId: string; purpose: Purpose;
  outputSchemaVersion: string; promptVersion: string;
  // Canonical server-derived union, must equal the complete message-part source closure.
  dataClasses: ReadonlyArray<DataClass>;
  sourceManifest: ReadonlyArray<SourceDescriptor>;
  messages: ReadonlyArray<{role: 'system'|'user'|'assistant';
    parts: ReadonlyArray<{text: string; sourceRef: string}>}>;
  maxOutputTokens: number; estimatedInputTokens: number;
  absoluteDeadlineAt: string; reasoningProfile: 'NO_REASONING'|'LOW';
}
interface NormalizedGenerationResult<T> {
  value: T; provider: ProviderId; modelId: string;
  attemptId: string; finishReason: string; latencyMs: number;
  usage: {promptTokens?:number; completionTokens?:number;
          totalTokens?:number; estimated:boolean};
  providerRequestId?:string;
}
```

Gateway alone authorizes outbound requests, with an unspent, one-time durable admission receipt; external adapter result is `unknown` until Zod **and** business-semantic validation. Allowed sanitized errors: `AI_RATE_LIMITED`, `AI_CAPACITY_UNAVAILABLE`, `AI_PROVIDER_UNAVAILABLE`, `AI_TIMEOUT`, `AI_ABORTED`, `AI_SCHEMA_INVALID`, `AI_OUTPUT_TRUNCATED`, `AI_PRIVACY_INELIGIBLE`, `AI_CONFIGURATION_INVALID`, `AI_OUTPUT_UNSAFE`. Never include raw SDK error/cause, headers, prompts, text, transcript or provider response in logs/error envelopes. **Provenance enforcement for `GenerationIntent`:** `messages.parts` and `sourceManifest` are built **only inside a trusted server assembler**; each outbound text part references exactly one descriptor, and `DERIVED_SUMMARY` recursively inherits the complete union of its `ancestorRefs` classes. `TRUSTED_TEMPLATE` contributes no real-data class but is only legal for immutable server-authored text. Unresolved, dangling, circular, missing/unknown refs and any mismatch between ancestry and `inheritedClasses` fail closed. Only after verifying **all** message parts and lineage does the gateway flatten `parts` into provider `role/content` messages. It rederives the canonical set before admission; it rejects differences from `dataClasses`, a synthetic+real mixture or an unapproved real-data combination. Bind final canonical class set and a privacy-safe *internal* versioned request identity to attempt/permit so a repair, fallback or prompt change cannot reuse a stale permit. Never log the manifest, prompt or unsalted content hash. A caller-supplied label/digest is not provenance proof. **Source ownership and scope — final R6-M01 rule:** A server-generated descriptor is **not** authorization. For every private root, resolve the exact source by an authoritative scoped query requiring `userId = authenticated principal`, `interviewId = authorized current interview`, expected `recordId` and immutable/versioned source identity. The resolved record's actual persisted owner/scope must match; do not resolve globally by plan slot/title/summary key. Same-user, different-interview sources are denied in Phase 4 v1 absent a separately accepted cross-interview feature, as are foreign-user records even with identical data-class consent. Derivative summaries inherit both the complete class union **and** the same owner/interview scope from all private ancestors; mixed user/interview ancestry fails closed. Trusted templates require an immutable server template registry entry; `SYNTHETIC_FIXTURE` requires a separately registered fixture ID/version, and may never reference candidate records. If a private source can be reassigned, mutated or deleted after lookup, fail closed until a verified source-version/authorization fence is available; Phase 4 v1 only uses immutable owner-bound inputs. Validate ownership before provider budget reservation, permit insertion or HTTP send; errors are `AI_PRIVACY_INELIGIBLE`/fixed internal source-resolution errors, with no PII or raw refs in logs.

**State-aware deadline for every network attempt, including repairs (R4-H01):** The gateway receives a server-validated `cutoffMode` derived from **durable** controller state, never caller-supplied mode or a nullable timestamp. For `PRE_START`, permitted only while a READY interview is held by a live START lease (`PLAN`, `START_BUNDLE`, and the Q1 `QUESTION` call), set `cutoffAt = min(readyExpiresAt, reservationExpiresAt, controllerLeaseUntil, requestDeadline)`. Do **not** reference `startedAt` or `effectiveDeadlineAt`: neither exists before Q1 is published. For `POST_START` (`QUESTION` Q2+, `FOLLOW_UP`, `CONTEXT_SUMMARY`), set `cutoffAt = min(controllerLeaseUntil, effectiveDeadlineAt, requestDeadline)` with any stricter hard-expiry or policy cutoff. All dates must exist and be valid for their mode, or fail closed with a typed configuration/state error; no undefined timestamp arithmetic or artificial early timer debit. Define `remainingMs = max(0, cutoffAt - serverNow - safetyMarginMs)`; do not admit/dispatch when below the benchmarked minimum viable call threshold. Bind request **and response consumption** to `min(providerTimeoutMs, remainingMs)` and the same attempt claim/permit expiry. Cancellation does not prove remote work stopped: unknown usage is conservatively counted. One bounded schema repair only after **fresh admission and permit**; never blindly repeat truncated output with unchanged output token budget. Optional PLAN+Q1 or `START_BUNDLE` repairs fit **one original START lease** and pre-start reservation/READY window; no PLAN call during PREFLIGHT and no lease extension merely to enable a second provider call.

**Q1 duration and monthly attribution — final R6-M02 business-effective timestamp rule:** The free-plan START/credit **business event time** is `startDecisionAt`: a trusted application server `Date` sampled exactly once **late inside the short Q1/P3 publication transaction, after the authoritative P2, READY, claim, lease, reservation and current policy checks, and before recording Q1/public event/P3 commit/receipt**. All eligibility predicates use that same instant. Derive the quota `periodKey` explicitly using the IANA `Asia/Kolkata` calendar month from `startDecisionAt`; verify it equals the still-live reservation period. Record `startedAt = startDecisionAt`, `effectiveDeadlineAt = startDecisionAt + plannedDurationMs`, and `hardExpiryAt = startDecisionAt + plannedDurationMs + approvedMaxPauseMs` in the **same** transaction as P3 consume, unique Q1, public event, and idempotency receipt. **Effect is valid only if that transaction durably commits.** `startDecisionAt` is the agreed *business-effective event time*, **not** MongoDB's physical commit instant, network ACK instant, original request arrival, or model dispatch. A majority-committed transaction may become visible/acknowledged *after* a monthly/READY cutoff; if its stamped `startDecisionAt` was valid then this is **by explicit product convention** an old-period interview with full planned duration measured from that earlier timestamp. Never claim a wall-clock pre-commit check proves that commit physically happened before midnight. This convention deliberately removes the impossible-to-guarantee commit-visibility cutoff and is an owner-visible monthly rule. Enforce a conservative **30-second initial guard band**: do not begin/continue a START publication transaction when `startDecisionAt` is less than 30s before the earliest READY, reservation or Asia/Kolkata month cutoff; reject/reconcile the pre-start operation without P3 consume and account provider usage conservatively. That guard reduces boundary ambiguity but is **not** the mathematical correctness guarantee; business-effective attribution is. Bound and instrument transaction/commit timeouts and use majority write concern, rejecting early when the guard cannot be met; benchmark actual Atlas Free tail latency before production and make any revised guard band a documented operational parameter. Delayed acknowledgment can shorten perceived remaining duration: if a verified platform delay exceeds the approved grace threshold, route to O-02 deterministic verified-pause/support adjudication, never silently extend or double-charge. If the short transaction aborts/commit is conclusively rejected, no Q1/credit exists; if commit ACK is uncertain, reconcile the immutable `operationId`, Q1 and P3 receipt before any replay/release. The same stable `startDecisionAt`/period must be recovered on replay, not resampled. PRE_START provider cutoff still uses READY/reservation/START lease, never an absent interview deadline.

**Groq model:** `qwen/qwen3.8-27b`. Test supported `reasoning_effort`/JSON-format combinations with synthetic cases; never force `reasoning_format='raw'` with incompatible JSON response format. Strict JSON Schema is **unverified for this account/model** and not required; baseline JSON object + Zod/semantic guard. Benchmark and feature-gate strict support if verified. Groq's Preview/deprecation status and actual account rate headers are monitored risks.

**Cloudflare model:** `@cf/qwen/qwen3.8-27b`, feature flag OFF. Test supported low reasoning; do not invent `reasoning_effort='none'`. Verify actual neuron coefficients/billing/usage and privacy before enabling. No automatic paid fallback.

## 5. Provider budgets: atomic, conservative, rollover-safe

**Admission ownership:** `P4-AI-01` implements the durable Mongo `providerBudgets`/`providerUsage`/provider-dispatch-attempt repositories and the only real `AIGateway.dispatch` barrier. `P4-INT-*` integrates it but must not introduce a second budget gateway. No in-memory-only production fallback. A separately constrained synthetic spike may use an explicit **synthetic-only entry path with an additional subcap**, but **never a separate provider-account capacity ledger** if it shares the same Groq organization or Cloudflare account. The consent/identity exemption applies only to audited synthetic fixture content, not to account RPM/TPM/RPD/TPD/neuron/concurrency or no-paid guards. Different actual provider organizations require verified separate account ownership, budgets and no-paid evidence; merely changing API keys is not isolation.

1. Key by **provider account/tenant** across **candidate, synthetic spike, repair and fallback attempts** using that same account, with applicable model-scoped sublimits, globally shared RPM/RPD/TPM/TPD (and any verified input/output-specific limits), concurrent calls and Cloudflare daily neurons. Never assume separate API keys multiply account allowance. Reserve input-token upper bound (measured tokenizer/estimate + margin) + max output tokens and provider-specific neuron upper bound.
2. In one Mongo atomic **shared provider-account** admission operation (or stricter account-serial gate if verified), validate all active limits and record exactly one unique `attemptId`, original window identifiers, reserved amounts, `dispatchStatus`, lease, permit validity and provider/versioned rate policy. Admission is **all-or-none for every outbound attempt**, including synthetic spikes. For candidate/private data, **join account-budget CAS, guarded P2 user/session writes, guarded `interviews` claim/version write, verified all-of source classes, attempt and permit insertions in the same short shared `ClientSession` transaction**. The interview conditional write must match owner, live claim nonce/generation, status and deadline and must conflict with abort/completion/reclaim; do not count a no-op or stale read. For isolated synthetic probes, P2/interview fences are not applicable, but **the identical provider-account budget CAS is mandatory**, with an extra synthetic per-spike sublimit. Use a proven account-serial CAS to avoid over-admission across processes; at one remaining account slot, only one candidate or synthetic permit may commit. No remote send without a confirmed permit and durable attempt admission. Prove the claim/budget/P2 ordering and concurrent shared-spike admission under two processes and real replica-set fault injection. Never hold the transaction across HTTP; avoid unbounded retries on the budget hot document.
3. **Minute boundary:** Do **not** simply reset minute RPM/TPM buckets at wall-clock minute boundaries. Prefer bounded, exact rolling 60-second request/token reservations in the account document, or a mathematically conservative alternative proved not to undercount any 60-second window. A two-bucket *weighted approximation* (`current + previous * remainingFraction`) is **not a strict safety bound** and is NOT adopted. The provider's actual algorithm/window alignment is unverified; treat local caps as conservative and use rate headers/429 to reduce effective ceiling. No claim of zero external 429s.
4. Preserve immutable **per-attempt** receipt of original accounting windows, upper-bound reservation and uncertainty across minute/day rollover. Releasing an expired concurrency lease **never** frees its uncertain token/neuron budget in the same active provider window. After a response, settle by `attemptId` exactly once, using known actual usage where reliable; no double settlement, and no debit to a new window for usage originally admitted in an old window. If actual usage exceeds reservation, add positive overage to the original window/usage record and clamp further admission; never silently drop it.
5. Keep the hot document bounded by pruning old minute admissions only after the maximum relevant rolling window; retain unresolved receipts in `providerUsage`/attempt storage with bounded retention and immutability. A late result is reconciled against that durable receipt even if removed from hot `activeAttempts`. Deduplication on `attemptId` is mandatory. An ambiguous timeout may have consumed capacity remotely; retain conservative spend until the provider window expires and preserve historical usage for audit.
6. Cloudflare day boundary uses verified UTC/provider day. Rollover does not erase old pending receipts or re-charge them into the new day. `Retry-After`/rate headers are advisory **lower** ceilings; account dashboard proof supersedes guessed limits. Admission can fail closed with `AI_CAPACITY_UNAVAILABLE`, never auto-enable paid service.

**Admission and send claim ordering (R5-M01/M02):** A candidate-private attempt is not authorized by an in-memory flag, a P2 snapshot read, or an unsettled `UnknownTransactionCommitResult`. Durably confirmed `dispatchPermit` and account budget receipt precede a one-use send claim; after the send claim, physical egress may be ambiguous and tokens remain conservatively charged. ## 7. State machine, deadlines, recovery and refund policy

Existing public enum unchanged: `DRAFT`, `PREFLIGHT`, `READY`, `ACTIVE`, `RECOVERING`, `COMPLETED`, `TERMINATED_INTEGRITY`, `ABORTED_PREFLIGHT`, `ABORTED_SYSTEM`, `EXPIRED`. START claims use internal `activeGeneration`, not a new public `STARTING` status. Terminal states immutable.

| Transition | Source of authority / atomic effect |
|---|---|
| DRAFT/config → PREFLIGHT | P2 valid; P3 reserve+interview+active-slot+idempotency in one Mongo transaction; set pre-start expiry immediately. |
| PREFLIGHT → READY | Idempotent accepted preflight; no LLM or timer; ready expiry bounded by reservation period end. |
| PREFLIGHT/READY → ABORTED_PREFLIGHT | Owner cancellation **or** server-observed pre-start expiry/month rollover. Pre-publication abort competes with Q1 commit using same READY+generation CAS; if abort wins release P3 once. |
| READY → ACTIVE | Current period/plan/owner/security/claim; Q1+public event+P3 commit+deadline+idempotency result one short transaction. |
| ACTIVE → ACTIVE | Finalize immutable answer + durable generation-needed intent; later commit Q-next by fenced attempt. |
| ACTIVE → RECOVERING | Verified provider/platform fault, persisted server cause/time/counters; client absence alone cannot trigger. |
| RECOVERING → ACTIVE | Explicit owner resume with current P2 user/session, bounded credited pause, bounded fresh **total** attempt allowance. |
| ACTIVE/RECOVERING → COMPLETED/EXPIRED | Deterministic terminal classifier from effective deadline and committed work; no client timer authority. |
| ACTIVE/RECOVERING → ABORTED_SYSTEM | Server-documented irrecoverable platform failure plus once-only P3 refund, never inferred from candidate inactivity. |
| ACTIVE/RECOVERING → TERMINATED_INTEGRITY | P6-only policy; existing consumed credit retained, cooldown enforced. |

**Exactly one server deadline policy (numbers still require owner signoff):** Persist `startedAt`, `plannedDurationMs`, `maxPlatformPauseMs`, **`creditedPlatformPauseMs`**, `hardExpiryAt = startedAt + plannedDurationMs + maxPlatformPauseMs`, and `effectiveDeadlineAt = min(hardExpiryAt, startedAt + plannedDurationMs + creditedPlatformPauseMs)`. `effectiveDeadlineAt` is never computed independently by individual endpoints. Candidate default `maxPlatformPauseMs=min(120_000,20% duration)` and finalization-only grace ≤5s remain **proposals**, not approved constants.

**Verified recovery incident ledger and pause proof:** For each platform-caused recovery incident persist `incidentId`, `recoveringSince`, cause/class, independently authenticated **server/provider evidence** of failed service and its bounded verified interval(s), a bounded global **canonical union of all eligible verified outage intervals** (`eligibleOutageIntervalUnion`) plus the monotonic **actually credited milliseconds** (`creditedPlatformPauseMs`) and a compact credit-decision receipt, `lastDecisionVersion`, and `recoveryAttemptsRemaining`; retain monotonic total attempt budget. **Never calculate eligible pause from `now - recoveringSince` by itself**: a lone 429/503 at 14:50 is not proof of outage through 15:20. Only policy-approved, server-supported service-unavailability intervals earn credit; intervals of browser abandonment or unverified elapsed time earn zero. Evidence may be an observed bounded failed request or continuously verified backend incident telemetry; never infer continuous outage from one `lastVerifiedOutageUntil` timestamp. Incident verification/granularity and treatment of missing evidence are **O-02** policy decisions, not invented runtime guarantees.

**One deterministic `resolveRecoveryAndDeadline(interview, verifiedEvidence, serverNow)` decision applied by `/resume`, `/reconcile`, `/complete`, `/advance` and server lazy reconciliation:** Under the same interview CAS/short transaction, canonicalize all verified time ranges into half-open `[startMs,endMs)` intervals, reject invalid/negative ranges, **merge overlapping/adjacent intervals both within and across incident IDs**, and intersect with the owner-approved eligibility window and `hardExpiryAt`. Merge with the **persisted global eligible-interval union**; compute `targetCreditedMs = min(maxPlatformPauseMs, measure(unionEligibleIntervals))` and `newCreditMs = max(0, targetCreditedMs - creditedPlatformPauseMs)`. Atomically persist the union and monotonic credited total through the same interview CAS, with a stable credit receipt. This credits only newly verified **uncovered** time even when evidence overlaps, arrives late/out of order or the cap has already been reached; it cannot multiply the capped total by changing interval boundaries or incident IDs. Exact-equality dedupe by `(incidentId,interval)` alone is insufficient. Use bounded/compacted interval storage and fail closed or support-adjudicate excess telemetry rather than silently dropping evidence and double-crediting. Recompute effective deadline **then** decide terminal or recoverable state. `/reconcile` is permitted to credit independently verified platform pause even when the user is absent, but cannot speculate about the missing interval or dispatch inference. A competing `/resume` and `/reconcile` must serialize and re-evaluate the same durable evidence on retry; no raw/old effective deadline may terminalize an incident before its eligible credit is considered. If evidence is insufficient for credit, use the approved zero-credit/uncertain-outage classification and support adjudication rather than granting idle time.

**Deadline/terminal precedence:** (1) nonterminal pre-start reservation expiry/period rollover; (2) P2 revocation/deletion/integrity terminal restrictions; (3) verified incident pause accrual once; (4) immutable `hardExpiryAt` cutoff; (5) recalculated `effectiveDeadlineAt`; (6) pending generation lease/attempt budget and recoverability; (7) normal next-turn eligibility. At/after the resulting effective deadline, no new generation can start. Finalization-only grace, if approved, applies only to a previously asked open question and cannot enable `/advance`. With ≥1 finalized answer normal expiry can yield `COMPLETED` with coverage metadata; with 0, normally `EXPIRED`; verified irrecoverable failure may yield `ABORTED_SYSTEM` only under O-02 evidence and P3 refund-once. P7 determines scoring sufficiency. Same persisted facts and time must not yield contradictory classifications due solely to endpoint ordering.

**Recovery and refunds:** Persist `recoveryCyclesUsed`, monotonic `attemptsUsedTotal`, `remainingAttemptsForOperation`, next permitted recovery time and a hard session-level provider-attempt cap. Recovery cannot reset attempts or infinitely cycle. After the shared resolver has applied provable pause, it classifies a pending intent as `RETRY_ELIGIBLE` (expired/no claim, within effective deadline, quota and attempts left), `RECOVERING` (documented platform fault, bounded cooldown/attempt path), or `TERMINAL` (deadline/hard stop, approved irrecoverable failure, or exhausted authorized attempts). These are **internal action outcomes**, not new public interview enum values. A live generation lease returns `PENDING`; `/reconcile` never dispatches AI, even when retry is eligible. Refund requires durable incident proof and an O-02-approved verified irrecoverable platform-failure predicate; passive inactivity alone does not earn refund. If the user left and evidence cannot establish a continuous outage, classify under the normal no-inactivity-refund rule and preserve an audited support review path. P3 refund operation is linked to interview and idempotent; the same incident cannot refund twice.

## 8. Create, preflight, start, cancellation and idempotent replay

### 8.1 One active user interview and reservation lifetime

**v1 policy proposal (O-09; not yet approved):** At most one nonterminal `PREFLIGHT|READY|ACTIVE|RECOVERING` interview per user at a time, even for paid sandbox/VIP; this is a resource/fairness policy **proposal**, not a previously frozen entitlement. Enforce with `interviews.slotActive = true` and a **unique partial index** on `{userId:1}` with filter `{slotActive:true}`, or an equivalent verified transactional user-slot CAS. Terminal transition clears `slotActive` in the same transaction. The simple boolean equality filter avoids relying on a particular MongoDB release's support for `$in` in partial indexes. Validate with real Atlas unique-index/race tests. Bounded per-user start-inference cap remains separate from P3 credits.

On `POST /interviews`, **conditionally write/fence both current P2 authorization documents inside the same short Mongo transaction** as P3 reserve, user active-slot claim, idempotency record and PREFLIGHT creation; if P2 deletion/suspension/revocation wins, no reservation or private record commits. Set `reservationExpiresAt = min(serverNow + approvedPreflightTtl, reservationPeriodEndUtc)`. On idempotent `POST /preflight`, apply the same P2 transactional write fence, set READY only if currently eligible and update expiry to `min(serverNow+approvedReadyTtl, reservationPeriodEndUtc)`; never extend beyond original month or permitted reservation lifetime. No numeric TTL is frozen without owner signoff. Any abandoned `PREFLIGHT`/`READY` expires to `ABORTED_PREFLIGHT` (`OWNER_ABORT|PREFLIGHT_EXPIRED|READY_EXPIRED|PERIOD_ROLLED_OVER`) and releases P3 once. **If and only if O-09 is approved**, `POST /interviews` MUST discover the requesting owner's existing active slot and run the common zero-provider resolver for **any** overdue `PREFLIGHT`, `READY`, `ACTIVE` or `RECOVERING` state (including pending generation, eligible verified pause, hard expiry and P3 settlement) **before** rejecting a new reservation; pre-start-only cleanup is insufficient. If the old session is lawfully terminal, clear `slotActive` with its terminal CAS and P3 settlement and then independently retry new create using the original idempotency key and all current P2/quota guards. If still legitimately nonterminal, return an owner-authorized `ACTIVE_INTERVIEW_EXISTS` response with `activeInterviewId`, `currentStatus`, and `allowedNextAction` (`RESUME`/`RECONCILE`/`COMPLETE` as appropriate), not an opaque permanent lock. If terminal reconciliation has an uncertain commit, return `RECONCILIATION_PENDING` with bounded retry/support path instead of claiming a free slot or double-reserving. Never disclose another user's interview ID, use GET to dispatch inference, or promise a worker on sleeping free hosting. Test return after app restart without a remembered interview ID. On `POST /interviews` and other relevant routes, keep expiry checks for stale pre-start reservations; `POST /start`, `/preflight`, `/abort`, `/reconcile` also reconcile expirations. GET stays read-only. After month rollover, old reservation must never fund a new-month Q1.

At START check actual current role/plan/plan-code/cooldown/VIP expiry, quota period, user status and **every** requested premium duration/feature/document permission; if READY config is no longer eligible, reject the old configured interview, release its unconsumed reservation and require a **new** validated configuration. No silent downgrade of 60 minutes to Free or sending stale premium documents.

### 8.2 Domain-linked idempotency records: crash safe

`idempotencyRecords` keyed by authenticated user+route+resource+keyHash and canonical payload digest. `IN_PROGRESS` includes **`operationId`/domain reference, owner claim nonce, `lockedUntil`, createdAt**, not an infinite lock. On identical-key replay: **always reauthorize against the current P2 principal/session and owner, and re-read the current interview resource before projecting a response**. Different payload ⇒ `409 REPLAY_CONFLICT`. If already durably committed, return a stable `operationReceipt` (`operationId`, `committedOutcome`, `committedAt`) plus **current candidate-safe resource status/projection**, not blindly the original READY/ACTIVE snapshot. If aborted/expired/completed/terminated, response must reflect that terminal status; if account was deleted/deauthorized, return the appropriate auth/not-found result **without leaking an old Q1, transcript or PII**. Domain-idempotent means **same side effect, not byte-for-byte immutable response body**. A historic `expectedVersion` is valid only to identify/replay that same committed operation, never to authorize fresh mutation. If genuinely claimed ⇒ bounded `202 PENDING` or documented `409 REQUEST_IN_PROGRESS` with `Retry-After`; if expired ⇒ CAS reclaim the same domain operation after durable reconciliation. `FAILED` must distinguish no-side-effect rejection from ambiguous dispatched/unknown-commit outcomes. Do not expire a record while it is still the live uniqueness guarantee.

**Preflight replay:** `POST /preflight` requires `Idempotency-Key` and canonical payload. A completed identical-key replay returns `committedOutcome=READY` and **the currently authoritative status**: READY only while still READY, otherwise a terminal/changed-state projection. No duplicate device check or credit action; no stale READY authorization after expiration or owner abort.

**Start protocol:** (1) authenticate/owner/current entitlement; (2) replay/domain reconciliation; (3) claim READY START lease with CAS and per-user attempt limit, keeping the original READY/reservation TTLs; (4) for each Q1 PLAN/START_BUNDLE/QUESTION send, compute the **PRE_START** §4 cutoff and atomically admit a **shared-account** provider budget receipt/**P2- and interview-claim-fenced permit with complete source-class checks** (§3), then perform the one-use authorized Qwen call outside Mongo txn; (5) validate output; (6) in **one** short Mongo transaction perform P2 authorization commit-fence, verify READY/claim/period/reservation and pre-start cutoff, persist Q1 plus **public-safe event**, business-effective `startDecisionAt`, corresponding deadlines and matching P3 period credit commit, mark idempotency success; (7) return committed Q1. No interview duration passes during Q1 generation; if initial Q1 output arrives after READY or reservation/lease expiry, discard it, abort/release once, and retain accounted provider use. Lost HTTP response must replay the **same committed operation**, never re-invoke the provider; return Q1 only if it remains currently authorized/playable, otherwise a safe receipt and current terminal-state projection (§8.2). Start cross-month after inference: discard stale Q, release old-period reservation and terminally mark preflight, without consuming new month credit.

**Owner `/abort` during START:** Allow it **until Q1 publication**, with an atomic race against the same `READY` CAS and reservation. If abort wins, invalidate/fence generation, release reserved P3 credit and return `ABORTED_PREFLIGHT`; external provider spend stays accounted and per-user attempt caps prevent free-tier abuse. If Q1 commit wins first, abort returns `INTERVIEW_ALREADY_STARTED` (no retroactive release); a separate post-start completion policy applies. No behavior based on client arrival time without atomic server ordering. Late Qwen results after abort cannot publish. This corrects v0.2's blanket block on abort during a live START claim and requires owner signoff of UX wording.

**Transaction uncertainty:** Use MongoDB driver-supported `UnknownTransactionCommitResult` commit retry/reconcile and `TransientTransactionError` transaction retry **only for safe deterministic DB operations**. A network error during `commitTransaction` does **not** prove rollback. Before any new external dispatch, credit release or refund, re-read authoritative interview/P3/idempotency records by stable operation ID; if committed, return persisted result. Do not invoke Groq inside a transaction retry callback. Use approved majority write concern, stable uniqueness and fault injection for create/Q1/finalize. All effects precisely one Mongo logical outcome even if client receives no ACK.

## 9. Turn finalization, durable intent and explicit advance

`POST /turns/:turnId/finalize` requires current owner Bearer, immutable canonical answer+revision, `expectedSequence` referring **only to candidate-facing lifecycle stream**, and `Idempotency-Key`/payload hash. In one short transaction, authorize/fence P2, store response uniquely, append public turn-finalized event, close turn and either set terminal if effective deadline reached or store durable `generationNeeded = {operationId,closedTurnId,slotVersion}`. ACK means answer + next-work intent is in Mongo. HTTP lost response replays receipt; a later new-key request must still hit unique turn/ownership guards.

`POST /turns/:turnId/advance` is **domain-keyed by `(interviewId,closedTurnId)`**. `Idempotency-Key` may still be required for request tracing/payload binding, but **202 PENDING is never cached as a permanently completed idempotent result**. On any authenticated call: if next question already committed, return its current **authorized** projection only while playable, otherwise the safe terminal/current-state receipt (§8.2); if live claim exists, return `202` with bounded pollAfter; if claim absent/expired and durable intent remains valid, claim/reclaim by CAS with a new nonce/epoch, increasing provider attempt count, then dispatch with fresh admission. The same caller key may be retried after lease expiry without being trapped in an old `202`. After all bounded attempts fail, transition to RECOVERING with durable cause/counters. No GET can perform an unbounded or billable dispatch.

Commit Q-next only when current P2 authorization fence, interview owner/status/deadline, domain `generationNeeded`, `generationEpoch`, `claimNonce` and unique logical question ID all match. The transaction must assert a matched live interview update **before** writing child question/events; otherwise abort all writes. Stale attempt may still cost provider tokens but can never commit another question. Internal diagnostic/retry/audit events must not change candidate `publicSequence` or turn preconditions.

`GET /interviews/:id/next`: read-only `COMMITTED|PENDING|LEASE_EXPIRED|RECOVERING|TERMINAL`, safe question/sequence/pollAfter, with owner auth and no-store; client explicitly calls `/advance` as needed. The absence of an always-on worker means no unattended progress while the browser is gone. On return, durable intent is reclaimable.

## 10. Resume, terminal reconciliation and cross-session ownership

`POST /interviews/:id/resume` requires a **currently valid authenticated app session of the same `userId`**, not necessarily the original `sessionId`; re-login/new device may resume if account ACTIVE, entitlement/cooldown/session and interview policy allow and not past hard expiry. No resume of another owner. A `logout-all` invalidates existing sessions, so new login/auth proof is required; it does **not** by itself irrevocably destroy a user-owned interview unless an explicit product policy says so. P2 status `PENDING_DELETION` or suspension always denies.

`/resume` and `/reconcile` must call the **same CAS-serialized recovery/deadline resolver (§7)** before attempting transitions. `/resume` may authorize bounded new attempts for an eligible pending generation; it must not silently call Qwen, reset the session attempt budget or give unverified pause for time the candidate was absent. A concurrent reconciler cannot terminalize using an uncredited old deadline. If the resolver returns `RETRY_ELIGIBLE`, `/resume` can re-enter ACTIVE and the user may explicitly invoke `/advance` (subject to the clock and consent). If `RECOVERING`, return reason/cooldown rather than an immediate no-progress ACTIVE bounce. If `TERMINAL`, prohibit further inference or resume and settle P3 under the chosen refund predicate. Repeated resume cannot double-credit or bypass hard expiry.

**Explicit overdue reconciliation:** `POST /interviews/:id/reconcile` is an authenticated, domain-idempotent, **zero-provider-call** command. It processes pre-start expiry/period rollover, verified pending pause, overdue ACTIVE/RECOVERING, outstanding `generationNeeded`, claim lease and monotonic attempt caps **in the §7 precedence order**. It returns a safe `reconciliationAction: PENDING | RETRY_ELIGIBLE | RECOVERING | TERMINAL` and authoritative current status; these labels are **response actions**, not public session states. A live lease yields PENDING; an expired lease plus remaining attempts can yield RETRY_ELIGIBLE only while within the recomputed effective deadline; an exhausted attempt budget cannot pretend to be retryable. Terminal classification is persisted once with P3 release/refund rules and `slotActive` removal. **If O-09 one-active policy is approved, owner-scoped, zero-provider overdue reconciliation is mandatory on `POST /interviews`** across PREFLIGHT, READY, ACTIVE and RECOVERING (§8.1); otherwise, cleanup/recovery may be invoked explicitly on the existing interview. it does not bypass P2 for new writes. Separately privileged cleanup after `PENDING_DELETION` may terminate/purge without reactivating user-owned state. GETs remain read-only. Unattended immediate completion on sleeping Render Free is not promised; before P7 scoring the durable terminal must be reconciled.

`POST /complete` applies the same terminal classifier and no extra AI; integrity termination remains P6-only. Terminal change clears `slotActive`, closes pending generation, cannot unconsume integrity credit or reopen. Under unresolved verified platform outage, document and surface a support/audit path rather than claiming an unverified refund; one P3 refund operation ID and robust unknown-commit reconciliation prevent duplicates.

Error classes include `AUTH_REQUIRED`, `FORBIDDEN`, `REPLAY_CONFLICT`, `REQUEST_IN_PROGRESS`, `INTERVIEW_STATE_CONFLICT`, `INTERVIEW_EXPIRED`, `INTERVIEW_ALREADY_STARTED`, `ACTIVE_INTERVIEW_EXISTS` / `RECONCILIATION_PENDING` (only if owner approves one-active policy), `RESERVATION_EXPIRED`, `AI_CAPACITY_UNAVAILABLE`, `AI_RATE_LIMITED`, `AI_PROVIDER_UNAVAILABLE`, `AI_SCHEMA_INVALID`, `AI_PRIVACY_INELIGIBLE`, `AI_TIMEOUT`, and relevant P2/P3 domain errors. A 401 refresh must retry only a truly idempotent command with the same key/body, never invent another mutation.

Public DTOs allow only current question text/id/type, open turn ID, session status/deadline/recovery display, authorized simple progress and *completed Free overall score only when Phase 7 permits*. **Never** return rubric, expected concepts, future plan, model prompt/metadata, private grades, raw events, response-scoped personal data from other principals, or premium details in Free API responses. Internal events live in a distinct logical stream and do not advance the candidate's public sequence, whether implemented in separate collection or explicitly separate typed storage.

## 13. Mandatory negative, concurrency and quality gates

The following are **required tests**, not currently passing evidence:

1. Same-key START crash before admission, after admission-before-dispatch, after dispatched-unknown, after Q1 Mongo commit-before-HTTP ACK; no permanent IN_PROGRESS and no duplicate P3 commit/Q1. Distinguish PRE_START cutoffs from after-Q1 effective deadline.
2. Same turn `/advance` returns 202 then lease expires: repeated call with same key reclaims or returns committed 200, never cached permanent 202.
3. Mongo `UnknownTransactionCommitResult` for create/Q1/finalize/reconcile; reconcile authoritative state before new model call/release; no callback-internal provider calls.
4. Simultaneous logout-all/single logout/status/consent/deletion vs **create+P3 reserve, preflight, resume, finalize, START Q1, and Q-next**; shared P2 user **and** session write/CAS wins in correct serialization order. If deletion wins, no new private PREFLIGHT/READY/ACTIVE state persists; if creation wins, later purge removes it. Real replica-set write conflicts are mandatory.
5. Synthetic candidate answer/summary/resume canaries absent from **all rubric-authoring** prompts for Q1/Q2/QN; present only when explicitly allowed in follow-up. A schema-valid `FOLLOW_UP` attempting an in-plan **other-topic `TRANSITION`** must be rejected; server-owned unscored transition cannot create a turn or inherit an unrelated rubric; new main uses separate `QUESTION` with fresh trusted rubric.
6. PREFLIGHT abandoned; READY expired; IST month rollover during slow Qwen Q1; transactional P3 release and new create, no stale period credit or slot. For READY at T0, send at T+1s, publish at T+40s (while pre-start windows remain valid): `startedAt≈T+40s`, full requested duration starts then. If TTL/lease expires mid-call, discard Q1; never dereference nonexistent `effectiveDeadlineAt` during PRE_START. PLAN+Q1 shares original deadline. Inject a paused Mongo commit crossing midnight/READY expiry: assert a **committed** old-month event retains the single previously valid `startDecisionAt`/period only if the business-decision instant and 30s guard were lawful, while an operation entering the guard band fails closed; never claim commit ACK time is the clock rule. No duplicate Q1/P3, and uncertain ACK reconciles by original IDs.
7. Owner `/abort` races Q1 publication: exactly one wins; if abort wins zero P3 commit, but provider admission remains accounted; caps stop repeated abuse.
8. 5 concurrent sandbox candidate create attempts using different keys: at most one active preflight/ready/active/recov slot if owner approves policy; index/transaction tested on actual Mongo.
9. Provider last-slot concurrent RPM/RPD/TPM/TPD/neurons across two processes; rolling-minute boundary attempt 12:00:55 vs 12:01:01 cannot over-admit under conservative policy. **R5-M02:** with one shared-account request capacity remaining, race synthetic spike and candidate admits on separate API processes: at most one permit commits, with no candidate consent exemption for non-synthetic traffic; separately verify spike subcap and no false isolation by different API keys.
10. Late provider response after concurrency lease expiry and minute/day rollover; original window charged exactly once, historical receipt not lost, no new-window debit.
11. Schema repair and PLAN+Q1 separate send each use distinct attemptNo/attemptId/admission; attempt lease expires mid-repair => second send skipped and no unearned budget consumption.
12. Interval-union pause evidence: same incident `[14:59:00,14:59:25)` and `[14:59:15,14:59:40)` credits 40 seconds, not 50; duplicates, distinct incident IDs with overlap, out-of-order/fragmented arrivals and simultaneous resume/reconcile are canonicalized and credited once, within max pause and hard expiry. RECOVERING provider returns healthy but client stalls: **one failure at 14:50** and no further proof must **not** earn time through 15:20 or a refund. A genuinely verified bounded outage can earn credit once; refund only under O-02 verified irrecoverable failure. Recovery cannot bounce or reset exhausted total cap.
13. Fault at T−10s, verified incident extends to T+20s: `/resume` races `/reconcile` on two processes; each resolves verified pause **before** expiration against the same CAS, stays within hard expiry, and cannot double-credit. Repeat with zero answers, prior answers, unverified incident, hard expiry exceeded and repeated recovery.
14. No requests beyond deadline then reconnect/new POST: pending `generationNeeded` + expired lease + remaining attempts resolve to `RETRY_ELIGIBLE` only if still within effective deadline, otherwise lawful `TERMINAL`; never silently dispatch AI from `/reconcile`, never double credit or strand old active slot. 16. Old session revoked, user logs in again: same user may resume only within current state/security/time rules; other user's session always denied.
17. Candidate event publicSequence remains contiguous as internal attempts/integrity events occur; expectedSequence does not spuriously conflict.
18. Free/Paid sandbox, ACTIVE/COMPLETED/EXPIRED candidate reads recursively exclude rubric, future plan, hidden private events, evaluations and premium detail; other user 403/404.

21. Atlas Free real replica-set contention/readiness/unique indexes, hot documents, 1–2-user realistic p95; 100-way tests demonstrate correctness not throughput.
22. Logs and exception canaries: no raw provider exception, key, transcript, user document or secret in any response/log/metrics.
23. Manual browser voice integration remains P5, proctoring P6 and evaluations/Free score/report P7: Phase 4 alone cannot claim these outcomes.
24. Completed `/preflight` key replay after `READY → ABORTED_PREFLIGHT` and completed `/start` key replay after `COMPLETED`, account revocation or deletion: same side effect, **current** safe terminal status, no stale playable Q1, no historical transcript leak and no fresh mutation from old expectedVersion.
